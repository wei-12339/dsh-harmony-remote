# ADR-0002：双原生客户端，共享协议和验收标准

状态：接受

日期：2026-08-30

## 背景

Android 和 HarmonyOS 在 VPN、后台生命周期、安全存储、通知和发布签名方面存在
明显差异。强制共用完整 UI/运行时代码可能降低 HarmonyOS 稳定性，也会限制
Android 对系统能力的正确使用。

## 决策

- Android 使用 Kotlin + Compose 原生实现。
- HarmonyOS 使用 ArkTS 及平台原生能力实现。
- 两端共享协议定义、错误码、权限语义、交互规范和 L0-L4 验收用例。
- 可通过 OpenAPI/JSON Schema 生成数据类型，但不要求共享 UI 运行时。

“统一客户端”定义为统一产品体验和协议，不等于强制一套代码运行在两个平台。

## 结果

优点：

- 更好处理各平台 VPN、后台和安全存储差异。
- 平台故障可以独立修复和发布。
- 协议和验收标准仍能保持功能一致。

代价：

- 需要维护两个客户端工程。
- UI 组件和部分业务逻辑会有重复实现。
- 必须建立协议一致性测试，避免功能漂移。

## 被否决方案

- 纯浏览器作为长期唯一客户端：难以安全保存设备密钥和实现可靠后台能力。
- 强制单一跨平台 UI 框架：在 HarmonyOS VPN/后台集成尚未充分验证前风险更高。
