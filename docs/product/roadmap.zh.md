# 分阶段建设路线

## Phase A：产品架构与安全基线

状态：本次完成。

交付物：

- V1 产品需求。
- Managed Gateway / Legacy Bridge 双模式架构。
- 设备绑定、权限、审计和紧急停止安全模型。
- 安装事务、升级和回滚原则。
- 兼容性数据字段、隐私边界和测试矩阵。
- 两项核心架构决策记录。

完成本阶段不等于产品已经可以一键安装。

## Phase B：Windows 探测与安装器 MVP

目标：先证明能可靠发现环境、生成计划、安装测试组件并完整回滚。

建议拆分：

1. Harness 接口/事件流发现工具。
2. Windows 环境清单和端口/服务冲突检测。
3. 安装计划 JSON 和用户确认界面。
4. 事务备份、安装、健康检查和回滚引擎。
5. 本地网关最小骨架，仅提供健康检查和设备配对实验。

退出条件：在测试机完成全新安装、重复安装、故障注入回滚和卸载保留数据。

## Phase C：安全网关 MVP

目标：手机不再直接访问 Harness。

范围：

- 设备密钥和一次性配对。
- 短期会话和设备撤销。
- Harness Adapter 能力探测。
- 工作区别名和最小权限。
- 本地审计和暂停远程入口。
- 请求幂等和基础事件恢复。

退出条件：完成未绑定设备拒绝、丢失手机撤销、重复请求和紧急停止测试。

## Phase D：Android 原生客户端

目标：用官方 Tailscale 作为网络层，客户端提供产品级设备和会话体验。

范围：

- Kotlin + Compose。
- Android Keystore 设备密钥。
- 二维码配对、会话、通知、审批和停止。
- 电池优化、其他 VPN、私人 DNS 和网络切换诊断。

退出条件：至少三个 Android 系统策略族完成 L4 验收。

## Phase E：HarmonyOS 原生客户端

目标：复用共享协议和验收用例，针对 HarmonyOS 生命周期做原生稳定性建设。

范围：

- ArkTS 客户端和现有 VPN Extension 整合。
- 系统安全存储、设备密钥和配对。
- LowMemoryKill、后台运行和断线恢复诊断。
- 与 Android 一致的权限、错误码和任务状态语义。

退出条件：拔 USB、移动数据、锁屏恢复和长会话场景达到 L4。

## Phase F：兼容性与发布体系

目标：形成持续积累的工程壁垒。

范围：

- 本地诊断包和用户预览。
- 自愿匿名兼容性上报。
- 自动化矩阵、错误趋势和设备验证标签。
- 签名更新、SBOM、漏洞扫描和自动回滚。
- 面向普通用户的安装支持和恢复流程。

## 推荐的下一步选择

Phase A 完成后，不建议马上同时开发安装器和两个客户端。下一步应从 Phase B
开始，并先做两周以内可验证的技术探索：

1. **B1 Harness 接口发现，推荐**：确认安全网关能看到哪些会话、消息和工具事件。
2. **B2 安装事务原型**：先做计划、备份、安装和回滚，不连接真实手机。
3. **B3 网关配对原型**：先证明设备密钥和撤销，不接入 Harness。

推荐先做 B1，因为它决定细粒度安全控制是否能够真实落地，也决定 Adapter 和
客户端协议的边界。B1 完成后再冻结安装器和网关 API。
